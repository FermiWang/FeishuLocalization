# 声纹识别（说话人分离）可行性研究 — 结论与验证记录

日期：2026-08-17 ｜ 验证机：192.168.100.179（Mac Studio, arm64, 96GB）

## 结论：可行，已原型验证通过

目标：对会议录音 mp3 做说话人分离，把讯飞转写文字按发言人区分，
再交给本地大模型整理（提升「主要参会人员观点」「观点冲突点」的署名准确度）。

## 技术选型

| 方案 | 结论 |
| --- | --- |
| **FunASR（paraformer-zh + fsmn-vad + ct-punc + cam++）** | ✅ 采用。中文优化、一次调用直接输出「句级时间戳 + 说话人聚类标签」、无需 HF token、ModelScope 直接下载 |
| sherpa-onnx | 备选。更轻量（ONNX），但说话人分离需自行组合 segmentation+embedding+聚类，工程量大 |
| pyannote | 排除。需 HF token 与模型协议，中文预训练不如阿里系 |

## 验证方法（本目录脚本可复现）

1. `say` 合成三人（婷婷/美佳/善怡）对话音频 `meeting3.wav`（65s，7 次发言轮换）
   —— 注意 macOS 未下载的新奇嗓音会静默回退默认音色，需用 Meijia/Sinji 等已下载音色
2. `diarize_test.py`：FunASR 一句一标签，输出 `diarize_result.json`
3. `align_test.py`：讯飞文本（`iflytek_mock.txt`，有意加入措辞偏差）与 ASR 结果做
   **字符级 difflib 对齐**，讯飞每句按字符多数投票继承说话人标签

## 实测结果

- 分离：3 人聚类稳定（发言人轮换全部识别）；错误集中在短句边界
  （一句尾被并入下一说话人）
- ASR 文字对带口音音色识别较差（"洛可"→"roco" 等）——**不影响最终方案**，
  因为 ASR 文本只用于对齐锚点，最终文本用讯飞原文
- 对齐后讯飞文本 7 个发言轮换的归属**全部正确**，包括含人名音译差异的句子
- 性能：65s 音频全程 34.9s（含 4 个模型加载约 10s）；估算 1 小时会议约 20–30 分钟，
  纯 CPU，可与 27B MLX 模型共存（96GB 内存充裕）

## 工程化建议（下一步实施）

1. 新增 `diarize.py`：mp3 →（ffmpeg/afconvert 转 16k wav）→ FunASR → 句级标签
2. 新增 `align.py`：讯飞文本 + 标签 → 带「发言人N：」前缀的转写
3. 整理 prompt 增加「转写中发言人N为声纹聚类标签，请结合参会人名单推断姓名」
4. 流水线：上传 mp3 + 讯飞文字 → 「开始整理」先跑分离对齐（后台），再调 LLM
5. 依赖：远端 ~/spk-test/.venv（python3.11 + funasr + torch 2.13 + torchaudio），
   正式化时迁为 meeting-minutes 独立 venv；模型缓存 ~/.cache/modelscope（约 1GB）
6. 可选增强：UI 上让用户把「发言人N」映射为真实姓名（试听片段）

## 已知边界

- 单人会议或只有一人发言时分离无意义（结果全为同一标签，可自动检测跳过对齐）
- 多人同时说话、远场嘈杂录音会降低分离质量；对齐+LLM 对标签噪声有一定容错
- 讯飞若导出带时间戳的文本，可进一步用时间轴直接映射，比重齐文本对齐更准
